# Authoring a new C# bundle on `waddle-sdk-cs`

Quick-reference checklist for the SuperPenguin C# port batch. Full
rationale, code samples, and gotchas live in `README.md` "Writing a
bundle" -- read that once; use this page as the per-bundle checklist
afterward. Two reference bundles exist to copy from:

- `bundles/csharp/superpenguin-roll` -- the first bundle authored directly
  on the SDK (`!roll`/`!dice`, with `kv`-backed cooldowns).
- `bundles/csharp/csping` -- the original feasibility-spike bundle, ported
  onto the SDK second (`!csping` -> `pong (c#)`, relay-only, no `kv`/`db`).
  Its git history shows the hand-rolled "before" (raw
  `System.Text.Json.Nodes` parsing, manual wit-bindgen `Relay.Push`/
  `Relay.Error` handling) next to the SDK-based "after" -- useful if you're
  porting an existing hand-rolled bundle rather than starting fresh.

## Checklist

1. **Directory**: `bundles/csharp/<your-bundle>/`, copied from
   `bundles/csharp/csping` (relay-only logic) or
   `bundles/csharp/superpenguin-roll` (needs `kv` cooldowns) as the closer
   starting shape for your feature.
2. **Business logic** -- one class per stage, deriving from
   `WaddleSdk.Stage.WaddleProcessStage`/`WaddleActionStage`. Write against
   `WaddleSdk.Types`/`WaddleSdk.Chat` POCOs and `IWaddleHost` only, never a
   wit-bindgen-generated type. Unit-test this class alone, on the host CLR,
   with local fakes (no WASI build needed) -- see either reference bundle's
   `tests/*LogicTests.cs`.
3. **`WaddleHostAdapter.cs`** -- copy verbatim from either reference bundle,
   change only the namespace. Do not hand-modify the capability mappings
   unless wit-bindgen's generated shape itself changed (toolchain/SDK
   version bump).
4. **`ProcessStageExportsImpl.cs`/`ActionStageExportsImpl.cs`** -- copy
   verbatim from either reference bundle, change only the namespace and the
   logic-class name/import. These are the two EXACT type names/namespace
   `wit-bindgen c-sharp` requires (see either file's own header comment) --
   do not rename.
5. **`.csproj`** -- copy `csping.csproj`. Must have, in order: the
   `IlcExportUnmanagedEntrypoints=true` property, the
   `<Compile Remove="tests/**/*.cs" />` item, the
   `<ProjectReference Include="../../../sdk/waddle-sdk-cs/waddle-sdk-cs.csproj" />`
   item, and the `<Wit Include="../../../wit/waddle-bundle/stage.wit" World="stage" />`
   item. **XML comments must never contain a literal `--`** (MSBuild's XML
   parser rejects it with `MSB4025`, not a runtime error) -- use a single
   `-` for a prose dash instead, unlike this repo's Markdown/Rust/C# `//`
   comment convention which permits `--` freely.
6. **`nuget.config`** -- copy verbatim (the `dotnet-experimental` feed is
   required; `Microsoft.DotNet.ILCompiler.LLVM` is not on nuget.org).
7. **`Dockerfile`** -- copy either reference bundle's, adjusting only the
   bundle path and output assembly name. Must `COPY sdk/waddle-sdk-cs
   sdk/waddle-sdk-cs` in addition to `COPY wit wit` and the bundle's own
   directory -- the `ProjectReference` in step 5 needs the SDK source
   present in the build context, a step easy to forget if you only copied
   the pre-SDK `csping.csproj`'s original Dockerfile (git history).
8. **Tests project** (`tests/<Name>.Tests.csproj`) -- copy either
   reference bundle's. Links your logic `.cs` files directly
   (`<Compile Include="../YourLogic.cs" />`), never
   `ProjectReference`s the bundle's own wasi-wasm `.csproj`. Copy
   `coverlet.runsettings` too, adding `[<AssemblyName>.Tests]AutoGeneratedProgram`
   to the `Exclude` list if your bundle is small (few source lines): xUnit's
   generated test-host entry point is permanently 0%-covered and can sink
   the 90% floor on a tiny bundle even though it dilutes away on a larger
   one (`csping`'s own `coverlet.runsettings` hit exactly this).
9. **`bundle.yaml`/`hub-manifest.yaml`** -- new `app_id`/`version`; if
   porting a PenguinTwitchBot/SuperPenguin feature, use the exact
   `author`/`license`/`category`/`source_url`/`notice` block documented in
   `README.md` "Porting more PenguinTwitchBot (superpenguin) bundles" --
   copy-paste the MIT notice verbatim, never paraphrase it.
10. **Build + validate**:
    ```bash
    docker build -f bundles/csharp/<your-bundle>/Dockerfile -t <tag> .
    docker run --rm --user "$(id -u):$(id -g)" -v /tmp/out:/out <tag>
    wasm-tools component wit /tmp/out/<assembly-name>.wasm
    wasm-tools validate --features component-model /tmp/out/<assembly-name>.wasm
    ```
    Exports must be exactly `waddle:bundle/process-stage` +
    `waddle:bundle/action-stage`; imports only `waddle:bundle/*` plus the
    allowlisted WASI p2 namespaces (`hub_api/services/bundle_component_validator.py`'s
    `ALLOWED_WASI_NAMESPACES`) -- no `wasi:http`, no `wasi:sockets` unless
    your bundle genuinely needs the guarded `http` import.
11. **Reproducibility**: a new bundle is NOT presumed byte-reproducible by
    default (`componentize-dotnet`/NativeAOT-LLVM is still experimental) --
    keep it out of `scripts/verify-core-bundles-reproducible.sh`'s gate
    (Rust-only today) and document the exclusion in your `hub-manifest.yaml`
    header comment, same as `csping`'s and `pyping`'s (gh-521), until two
    independent `--no-cache` builds are confirmed byte-identical.
12. **Wire into the seed catalog** (`bundles/core-bundles.yaml`) and add a
    `make test-<your-bundle>` target + `scripts/test-<your-bundle>.sh`
    mirroring `scripts/test-csping.sh`/`scripts/test-superpenguin-roll.sh`.
